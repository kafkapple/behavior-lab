## tldr

1. **SBeA 저자 파이프라인을 먼저 돌려라.** 우리 데이터(`*-caliParas.mat` + `*-camera-#`)가
   저자 코드가 기대하는 입력 형식 그대로다. 그런데 **코드를 클론한 적이 없다.**
2. 우리가 짠 것(DLT 삼각측량 + 카메라 순서 24순열 탐색 + 좌/우 재라벨)은 **저자 파이프라인의
   일부를 손으로 다시 만든 것**이다. 저자는 epipolar 제약으로 뷰 간 조합을 재투영 오차
   최소화로 이미 푼다.
3. social 개체 분리 = 저자 tracker 의 5단계 중 5단계. **설계 대상이 아니라 실행 대상.**
4. "정량 3D 는 별개 프로젝트 규모" 도 틀렸다. SBeA 는 **few-shot 설계**(윤곽 라벨 ~400-800
   프레임)이고 identity 는 label-free 다.

## 1. 사실 정정 (260729 검증)

출처: Han et al., *Nature Machine Intelligence* 6:48-61 (2024),
`10.1038/s42256-023-00776-5` · 코드 `github.com/YNCris/SBeA_release` ·
`README_SBeA_tracker.md` (직접 열람). 3-verifier 교차검증 3/3 일치.

| 초판(260727) 서술 | 실제 |
|---|---|
| social 분리를 SAM2 2-instance 로 우리가 설계 | 저자가 **VisTR 기반 video instance segmentation** 으로 구현·배포 |
| 카메라 간 identity 매칭을 재투영 일관성으로 우리가 설계 | 저자가 **epipolar 제약 + 재투영 오차 최소화**로 이미 수행 |
| identity 는 미해결 | **label-free / zero-shot, bidirectional transfer learning, >90%** (EfficientNet) |
| 정량 3D 하려면 새 모델 학습 = 별개 프로젝트 | **few-shot 프레임워크** — 윤곽 라벨 ~400-800 프레임 |
| 왜곡 계수 미배포 = 왜곡 미모델링 | 저자는 **체커보드 Zhang 방식**(MouseVenue3D)으로 캘리브. 왜곡은 캘리브 단계에서 처리됐고 배포된 `cam_mat_all` 이 그 결과물 |

**우리가 가진 것과 없는 것**: 배포 자산(영상 200 + `caliParas.mat` 50 + csv 8 + DLC ckpt 3)은
받았으나 **파이프라인 코드는 클론한 적이 없다**. 그래서 손으로 다시 만들었다.
동봉된 DLC 스냅샷은 저자 3모델(분할·포즈·ID) 중 **포즈 1개**일 뿐이다.

## 2. 저자 tracker 파이프라인 (5단계)

`README_SBeA_tracker.md` 인용 요지:

1. `configfile.yaml` 생성/로드
2. 경로 설정 — `*-caliParas.mat`, `*-camera-#.avi`
   ← 우리 데이터는 `rec10-M2-20221108-caliParas.mat` · `...-camera-0.mp4`.
   **stem 은 일치, 컨테이너만 avi↔mp4 차이.** 코드가 확장자를 하드코딩했는지 S1 에서 확인할 것
   (트랜스코딩이면 비용 무시 가능, 리더가 다르면 손볼 지점)
3. 로드·라벨·학습 — 3모델 동시: VisTR 분할 · DeepLabCut 포즈 · EfficientNet ID
   (학습데이터 생성은 YOLACT++ 기반)
4. 평가 (선택)
5. **"Predict 3D poses with identities of new videos"** → `.mat` 로 "3D skeletons rotated to
   ground with identities" + JSON 분할결과 + CSV identity

우리 파이프라인에 없는 것: 분할·identity·지면 정렬(ground rotation). 있는 것: DLT 삼각측량뿐.

## 3. 우리 25 px 잔차와의 관계 — 260816 종결: 대조할 저자 수치가 없다

⚰️ **아래 3문단은 260816 폐기.** 게재본 PDF 전문 확인 결과 전제가 틀렸다.

- **논문은 3D 재투영 잔차 절대값을 보고하지 않는다.** 본문·전 figure 캡션·Methods·
  Extended Data 전수 grep. px·mm 어느 단위로도 없다.
- **논문의 px 오차는 전부 2D 포즈 예측 r.m.s.e.** (수동 라벨 GT 대비, 축 0~20 px).
  우리 24.7 px 은 재투영 잔차 — **다른 양이라 비교 자체가 성립하지 않는다.**
- **Fig. 6j 는 없다.** Fig. 6 = a~h(조류·개 응용)뿐.
- ❌ **"저자가 '재투영 오차는 카메라 커버리지가 불완전할수록 커진다'고 적었다(개 데이터)"
  는 논문에 없는 서술이다.** 우리 주변부 잔차 증가 관측의 저자 측 근거는 현재 없다.

그러므로 잔여 질문은 **"우리 24.7 px 이 저자 파이프라인에서도 나오는가"** 로 남되,
답을 얻는 유일한 길이 §4 S2(블랙박스 실행)이며 그 비용이 재평가됐다.

## 4. 착수 순서 (비용 오름차순, 각 단계가 다음 단계 필요성을 판정)

### S1. ✅ 완료 (260816) — 판정: 기준선 부재

클론 `f7e7e41`(2026-04-13, 234 MB) + 논문 전문 확인. 결과 3건:

1. **저자 보고 재투영 절대값 없음** → "같은 자릿수인가" 판정 불가. S1 은 판정 불능으로 종료.
2. **코드는 바이너리** — SBeA 자체 로직 54개 `.pyd`(PE32+ Windows DLL, `cp39-win_amd64`).
   소스로 열려 있는 건 VisTR·YOLACT 등 서드파티뿐. 진입점 = `gui/main.py` 260 바이트 런처.
3. **우리 재구현은 저자와 같은 구조였다** — Methods verbatim 확인. 삼각측량 = SVD 최소자승,
   개체-뷰 배정 = 전순열 탐색 후 최소오차 선택. 우리 24순열 탐색과 동형.
   빠진 건 **BA 와 지면 정렬 2단계**로 좁혀진다(`bundle_adjustment.pyd`·`Rot_ground_screen.pyd`).

**"S1 전 추가 분석 금지" 는 해제된다.** 단 해제 사유가 기준선 확보가 아니라 부재 확정이므로,
아래 S2' 가 새 선행 조건이다.

### S2'. ✅ 완료 (260816) — BA 부재가 잔차의 29% 를 설명한다

`scripts/sbea_bundle_adjust.py`. 외부 파라미터만 재적합(카메라당 회전 3 + 이동 3,
카메라 0 고정 = 18 자유도). 3D 점은 매 스텝 DLT 재계산이라 자유 파라미터 아님.

**held-out 10세션**(fit 미사용, 캘리브 그룹당 5/5 분할): 재투영 **24.80 → 17.62 px (−29.0%)**,
10/10 개선. 독립 지표 본 길이 rCV **0.2345 → 0.2255 (−3.8%)**, 9/10 개선. 중앙선 대조 −8.7%.

과적합 아님의 근거: ① held-out 개선폭(−29.0%)이 fit(−26.0%)보다 크다
② 120→800 프레임 확대에 결론 불변(260728 좌/우는 여기서 −31%→−2% 로 붕괴했었다)
③ 보정량이 회전 1.1~2.0°·이동 베이스라인의 2.5~4.2% = 캘리브 드리프트 규모.

**관절별 분해**(held-out): 중앙선 19~21 → **10.7 px**(−46%), 대칭 25~26 → **22 px**(−14%).
→ 260727 의 "잔차 바닥은 분해 불가" **철회**. 그 바닥은 캘리브 성분이 지배했고 실제 2D 국소화
바닥은 10.7 px 다. 대칭/중앙선 비가 1.2~1.4 → **2.0~2.1** 로 벌어져 **좌/우가 최대 덩어리**가 됐다.

**남은 잔차의 성격은 기하가 아니라 검출이다** — 재투영이 29% 내려가는 동안 rCV 는 3.8% 만
움직였다. 사지 kinematics 미지원 결론은 **불변**.

**판단 (260816)**: 본선 파이프라인 통합 **보류** — 유일한 소비처가 SAM2 프롬프트라 7 px 개선의
downstream 가치가 미검증이고, 통합하면 자유 파라미터가 파이프라인에 상주한다. 재검토 트리거 =
정량 3D 를 실제로 쓰는 소비처 발생. 그때도 **그룹별 1회 적합 상수 고정**(세션별 재적합 금지).

> 근거 전문 = vault `[[260816_behaviorlab_sbea_bundle_adjustment]]`.

### S2. 저자 pretrained 로 individual 세션 1개 재현 — 🔴 **260816 NO-GO**

**착수 안 한다.** S2 의 목적은 "우리 24.7 px 이 왜 그런가" 진단이었는데 S2' 가 답했다
(캘리브 드리프트 29% + 좌/우 + 국소화 바닥 10.7 px). 남은 건 *확인* 가치뿐이고
아래 비용에 미치지 못한다. **재검토 트리거 = social(S3) 을 실제로 하기로 할 때** — 그때는
어차피 같은 Windows 관문을 통과해야 하므로 S2 가 부산물로 딸려온다(§S3).

⚠️ **260816 정정: 코드 판독으로는 아무것도 확인할 수 없다.** 전부 컴파일 바이너리다.
남은 건 **블랙박스 실행 후 출력 대조**뿐이고, 선행 조건이 늘었다:

- **네이티브 Windows** 필요 — `.pyd` 는 WSL 에서 로드 불가. WSL `behavior-lab` env 와 별개.
- Python 3.9.15 · torch 1.13.1 · CUDA 11.7 · `pywin32` 고정 env (`environment.yml`, Windows pin).
- **GUI 전용** — headless 배치 경로 미제공.
- 입력 `*-camera-#.avi` 명시 → 우리 `.mp4` 트랜스코딩 전제 (확장자 하드코딩 여부는
  바이너리라 확인 불가. 구 O1 은 이로써 종결 — 확인 대신 트랜스코딩으로 회피).
- 저자 3모델 중 배포된 건 DLC 스냅샷뿐. 분할·ID 모델 학습 필요 여부 미지수.

### S3. social 세션 — 저자 경로로 실행 — 🟡 **260816: 데이터는 있고 관문은 Windows 하나**

데이터 확보됨(30세션 17G). 5단계 predict 를 돌린다. 필요 라벨은 few-shot 규모
(윤곽 ~400-800 프레임). identity 는 label-free 라 라벨 불요.
**우리가 설계했던 SAM2 경로는 폐기 유지** — 저자 VisTR 분할 + EfficientNet ID 가 논문 검증됨.

**260816 실측 — 유일한 실질 관문 = 네이티브 Windows env 1개.** S2 와 같은 관문이므로
비용은 공유된다(둘을 따로 세지 말 것).

| 경로 | 실행 가능? | 비용 |
|---|---|---|
| 저자 tracker 전체 (`.pyd`) | 네이티브 Windows 만 | env 구축 + GUI 조작 + mp4→avi |
| VisTR 만 Linux 에서 | 🟢 **가능** — `train_utils/vistr/main.py` 는 argparse 완비 순수 `.py` | 단 COCA 데이터 생성·ID 모델·3D merge 가 전부 `.pyd` |

🔴 **VisTR 만 떼어 쓰는 길로 새지 말 것.** 닫힌 건 SBeA 고유부(COCA 증강·identity·3D 병합)이고,
그걸 우리가 다시 짜는 순간 **260729 에 반성한 바로 그 재구현**을 반복한다.
social 을 하려면 Windows 관문을 통과하는 게 정공법이다.

### S4. 구조 변경 — 🔴 **260817: 후처리 재라벨 계열은 종결. 남은 건 구조 변경뿐**

R1 결과(`[[260817_behaviorlab_sbea_lr_after_ba]]`): BA 로 캘리브 오차를 걷어내 좌/우가 최대
덩어리가 된 상태에서도 Viterbi 완화는 held-out rCV 를 개선하지 못한다. 400프레임 PASS 는
선택 인공물이었고 800프레임에서 뒤집혔으며, lam 전수 스캔에서 부호가 lam 에 따라 바뀐다.
⇒ **`--resolve-lr` 기본 off 확정. 후처리 재라벨로는 안 된다.**

**단 S4 도 착수하지 않는다** — 정량 3D 소비처가 없는 한 신규 학습은 비용 대비 가치가 없다.
트리거 = SBeA 3D 를 SAM2 프롬프트 이상으로 쓰기로 할 때. 아래는 그때의 설계 근거다.


- **같은 단일개체 아키텍처 finetune 은 좌/우 문제를 못 고친다.** 원인이 데이터량이 아니라
  구조다 — part heatmap 이 독립이라 스켈레톤 제약이 없고, 단일 시점에서 자기폐색 시
  좌/우는 정보이론적으로 미결정이다. 데이터를 더 줘도 이미지에 없는 정보는 안 생긴다.
- **구조를 바꾸는 게 답**: multi-animal DLC 의 **PAF**(part affinity field)는 사지 연결
  방향을 예측해 조립 단계에서 좌/우·개체 혼동을 줄인다. 또는 SBeA 처럼 분할 윤곽으로
  몸통 방향을 먼저 잡는다.
- 신규 대규모 학습은 **최후 수단**이고, S1-S3 를 건너뛰고 여기로 가면 이미 있는 걸 또 만든다.

## 6. 방법론 경고 (S1-S4 전 구간 적용)
