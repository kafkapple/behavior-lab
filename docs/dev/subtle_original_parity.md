## Critical checks before claiming parity

- **Input identity:** the original CSV demo has 12,083 pose rows but its MP4 has 12,000 frames. The viewer warns about the mismatch; neither app can infer the correct offset from filenames alone.
- **Model portability:** a saved original `.pkl` may depend on its Python/package versions and node schema. Do not unpickle arbitrary files or claim it is interchangeable with this viewer's saved model without an isolated compatibility check.
- **Deployment identity:** justinstorage reports `SUBTLE_storage` commit `23feb60`, and its `engine/subtle/mapper.py` SHA-256 matches the local clone byte-for-byte. Justingpu2 reports `SUBTLE_gpu` commit `08ea907`; its `gpu_server.py` differs from the local clone. A live production `.pkl` was not available in the signed-in administrator account's Model tab. A read-only query of justinstorage's `file_metadata` database counted nine `subtle_pkl` entries under four users, but zero owners with both a model and CSV entry. No other user's object was downloaded. Do not equate this viewer's local `model.pkl` with an original production file.
- **Group claims:** original Group A/B upload does not itself validate animal assignment. G3's meeting note states pain/stroke aims, but none of its eight JSONs has an animal-level treatment group; the current G3 project is inspection only. Baseline M3 is excluded from the current comparison by the 2026-10-30 decision.
- **Statistics:** local BH correction is within the selected cluster level; browsing other levels adds selection that this correction does not cover. CORT folder-derived groups remain exploratory.

The remaining feature work is original PKL model interoperability, arbitrary video pose inference, image/keypoint label editing, and account-backed upload/result workflows. They require protocol and service tests before marking the app identical to the original. The isolated CSV workflow record is `outputs/subtle/original_demo_fit/261030_csv_fitmap/README.md`.

## Remaining implementation gates

1. **Original model import:** obtain a model plus its exact input CSV schema from the same owner, check version and dimensionality in a sandbox, then compare mapped frame labels against the original tool. The admin account's Model tab was empty and the metadata database had no owner with both a model and CSV entry, so this parity check has no paired fixture yet.
2. **Arbitrary video prediction:** accept a user-selected composite video, preserve its fps and camera geometry, choose a pose model, show per-stage progress, and save keypoints/3D with provenance. Check one complete video in both the original tool and this viewer. The fixed CORT toy does not satisfy this gate.
3. **Label editing and service features:** define an annotation save format, round-trip edits, then address account permissions, upload, result inventory, ZIP download, and multi-user isolation. The local viewer must not show public/private controls unless they actually enforce access.
