# SUBTLE walkthrough: video → keypoints → project → train → map

The viewer opens AVATAR `*.json.gz` with `skeleton3d` and optional `keypoint`/video, or the original app's `avatar_subtle` merged CSV beside a matching MP4. Its **Video tutorial** module makes a real 300-frame example from the CORT source video, using the SLEAP 1423 checkpoint on eren. The Mac hosts the viewer and saves outputs; SSH access to eren is required for this inference step. Other raw videos need the AVATAR upstream pipeline. The viewer never changes the source input; new labels go into `*.subtle.json` sidecars. For transitions, DIB and TPI, see [the focused survey](subtle_transition_dib_tpi_survey.md). For the original app's source-verified feature inventory, see [the parity check](subtle_original_parity.md).

Run `subtle` once. Choose **Sample** at the top: **CORT** shows the eight-session comparison, **G3** shows Shin Juhee's G3 consistency checks, and **Train/Map** shows the saved model and held-out mapping record. **Original SUBTLE** opens the source CSV/video example. Then click **저장 결과** for prior figures or **처음부터 따라하기** for this full guide inside the app. Selecting a sample changes the data root and its project list; it does not rerun analysis.

**G3** is the identifier in the recordings delivered after the meeting; it is not an experimental group assignment. There is no **G2** sample in the inspected local set. **Train/Map** is an isolated copy of CORT data used to test that a trained SUBTLE model can be saved, reloaded, and applied to two other sessions. Its one project group is a workflow role, not a treatment group.

## 2. Inspect the input

For a video-only start, open **2 · Keypoints → Video tutorial** and press **Open completed 300-frame toy**. This local example was generated on 2026-10-29 using the verified eren SLEAP checkpoint; its JSON and all six video files were checked at 300 frames. To repeat the upstream prediction, press **Predict keypoints again**. It cuts a real CORT clip on eren, runs SLEAP, downloads `tutorial/cort1_toy.json.gz` and the composite video, and splits five camera views. The step progress shows clip, inference, download and validation. Press **Reload session list**, open the toy session, turn on **Conf %**, and compare points, edges, video and 3D motion. `tutorial/provenance.json` records source, model and time. This one animal cannot support group statistics; use cohort examples for that stage.

For the already labeled eight-animal example, press **Open CORT two-group example** in Video tutorial. This loads `cort_vs_veh`, opens its first session, and starts **Compare groups**. The Stats table and PNG show one dot per animal and mean ± sample SD bars. Then open **DEK → Compute DEK**; watch the session-level progress, choose vertex/edge/angle and derivative, and save CSV/PNG. These folder-defined groups are provisional. This example uses existing fit sidecars; it does not demonstrate a new trained model. For new training, follow steps 3–4 below.

Wait for the Sessions scan to finish. Click one session. Check that the 3D skeleton moves, frame count is plausible, and available camera overlays align with the video. The `Quality` tab runs label-free consistency checks; it is not ground-truth 3D accuracy. For G3, first compare the provided keypoints with the five camera views and note the shorter keypoint streams reported in the G3 data plan.

**View settings** defaults to the BS AVATAR body-part colors: the same joint has the same color in video and 3D, and an edge uses its destination joint's color. The separate Cluster ID badge shows the selected cluster color. Switch to **Legacy cluster edges** if you want the old label-colored overlay. Dashed/faint edges indicate low 2D detector confidence; **Conf %** overlays the numeric values.

Upstream stages for a new recording are: composite video → five camera views → 2D keypoints (SLEAP or Lightning Pose) → calibrated 3D skeleton → viewer input. The tutorial runs this path for its fixed toy clip. The AVATAR rig's cell geometry lives in `configs/rig/avatar.yaml`; do not infer camera coordinates from the displayed video size.

## 3. Create a project and assign sessions

Open the **Project** tab. Type a project name, for example `cort28d_review`, then type a group name such as `cort`. Open each intended session in the left panel and click **+ add open session**. Repeat for `veh` and its sessions. Add a description and the animal, condition and date fields, then **Save**. Use **Load** to reopen the saved project. Project membership is the data selection; the fit runs jointly on all its sessions so cluster IDs are comparable. Check every group and session before running: the group labels should come from metadata, not guesses about file names.

For G3, Sample → G3 opens the copied JSON files and saved single-group inspection project. Set actual groups only after the experimental assignment is confirmed; a new joint fit or saved-model map is needed for comparable labels. Raw videos alone are not a viewer input.

## 4. Explore or save a mapping model

Open **3 · Discover & map** and set `frames/session` (0 = all), `seed` (0 = repeatable), and `Method` there.

- **Explore clusters**: fit the chosen method jointly and write session sidecars; no reusable model is saved. The default is original SUBTLE's UMAP + Phenograph. The B-SOiD option has UMAP neighbors and HDBSCAN minimum-cluster-size settings; it is for exploration only.
- **Train & save**: enter a model name, then start training. It fits the project sessions and saves `.subtle_models/<name>/model.pkl` and `model.json` under the data root. Train requires a `subtle/*` method. The model record includes source paths, seed, method and creation time.
- **Map new sessions**: choose a saved model, assign target sessions to the current project, then map. It labels all frames of those sessions and records model name and mapping time in sidecars. The selected model, not a new fit, supplies the mapping. Check the fit ID and mapping log; mapped training frames can differ from original fit labels.

The completed save/load check is isolated from the original CORT root: choose Sample → Train/Map, load project `cort_trainmap_demo`, and open **Discover & map**. Model `cort6_3000_seed0` (fit `3d203e49`) trained on six sessions × 3,000 frames; the saved model mapped two held-out sessions on all 11,999 frames each. The training-source sidecars cover only 3,000 frames; the held-out sidecars cover all frames. The original `cort28d` sidecars retain fit `9fc3c01d`. The one project group describes a workflow test, not a treatment condition; do not use its role split for group statistics. The exact paths and counts are in `outputs/subtle/cort_trainmap_demo/261030_train6_map2/summary.json`. A separate original-format CSV check trained on 1,000 rows and remapped all 12,083 rows of the source demo (fit `0817f965`); it is a same-recording workflow check, not held-out validation, under `outputs/subtle/original_demo_fit/261030_csv_fitmap/`.

The expandable method table in Discover & map distinguishes the runnable SUBTLE and B-SOiD paths from Keypoint-MoSeq. Keypoint-MoSeq uses a separate uv environment in this repository and its fit is not yet connected to this viewer; the [method paper](https://doi.org/10.1038/s41592-024-02318-2) and [fitting documentation](https://keypoint-moseq.readthedocs.io/en/latest/fitting.html) describe its temporal model and parameters. B-SOiD's UMAP/HDBSCAN route is described in its [method paper](https://www.nature.com/articles/s41467-021-25420-x). Do not compare raw cluster IDs across these methods.

The Discover & map job line and bar show the stage, percent, elapsed time and error. The Log module has detailed messages. SUBTLE fits can take minutes; start with a small `frames/session` limit before deciding on a full fit. Seed stability launches three fits and is a separate, longer job.

## 5. Read and export

The timeline and map show labels for the selected level. Frequency requires complete labels and one fit ID across sessions; a red Σ badge means the comparison is invalid. Stats, DEK, level sweep, seed stability and Export results are separate actions. For any group claim, inspect animal-level shares, corrected statistics, and bouts/transitions; a cluster map alone is insufficient. The Stats tab can export CSV/PNG; Export results writes a bundle under `outputs/subtle/<project>/`.

In **Stats**, the selected level's cluster shares appear first as one card per cluster. Blue and orange dots are animals, the bar is mean ± sample SD, and a gold outline plus `*` marks corrected p<.05. Open **Advanced** only for level sweep and seed stability. In **DEK**, gold outlined cells and the star jump buttons identify corrected p<.05 cells across all feature types and derivatives. These are exploratory signals. In the completed CORT L8 example, nine share tests had no corrected p<.05 (minimum .0804); four of 756 DEK cells did (minimum .0191). The group names came from folders, not verified experimental assignments. The saved graph and exact cells are under `outputs/subtle/cort_vs_veh/261029_235721_L8_descriptive/`.

The G3 source contains a previous `subtle` result. Opening it is for inspection; Train or Map creates this viewer's own sidecar. Keep the previous result and the new fit distinct, and record the seed, source file and model ID when comparing them.
